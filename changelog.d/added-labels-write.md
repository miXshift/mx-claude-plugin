- **Change the labels on your items and campaigns from the plugin, with a preview first.** `mixshift labels preview` builds a change and shows exactly what it would do before anything is touched: how many items or campaigns change, which accounts it reaches, what was left out and why, warnings, and a before and after sample. Choose items by ASIN or campaign id (`--ids`, `--ids-file`), by a current value (`--where item_group="Water Bottles"`), from a CSV file (`--file`), or rename a value everywhere (`--rename item_group --from ... --to ...`). `mixshift labels commit <id> --commit` applies that exact preview, only after you confirm it; without `--commit` it shows the change set and sends nothing. An item someone changed after your preview is left exactly as it is and reported as stale, the rest still apply, and the command exits non-zero so a partial result is never mistaken for success. `labels undo <id>` previews the reversal, `labels sets` and `labels set <id>` show past and pending changes and who made them, `labels cancel <id>` drops a preview, and `labels field-name` gives an account its own name for a field. A change set holds up to 1,000 items or campaigns. A `--file` CSV works best when many rows share the same values: each different combination of values becomes its own change set (each committed and undone separately), and one file may make at most 10. A file cell cannot start with = + - or @ (a spreadsheet would read it as a formula), so set such a value with `--set` instead. `labels cancel` and `labels field-name` also need `--commit`. These commands work once label editing is turned on for your account; until then each one says so in a sentence and changes nothing.
